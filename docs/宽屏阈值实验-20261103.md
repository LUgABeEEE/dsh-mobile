# 宽屏阈值实验：按「设备短边」判定，避免横屏手机被当成平板

实验分支 `exp/wide-by-shorter-side`（从 `upstream/main` = 0.8.1 / `42cabbd` 切出），只推 fork `LUgABeEEE/dsh-mobile`，未建 PR、未改 upstream。

这是一份实验记录，不是发布文档；因此没有 `.en.md` 对照，也没有写进 `docs/README.md` 的专题索引与 `CHANGELOG.md`（0.8.1 已发布，本次不是 release 内容）。

## 结论

| 视口（屏幕） | 改前 | 改后 | 依据 |
| --- | --- | --- | --- |
| 932×430 手机横屏 | 宽布局：侧栏常驻、无返回栏 | 抽屉布局：侧栏浮层、返回栏回归 | 【实测】Chromium 几何表 |
| 909×1314 竖屏平板 | 宽布局 | 宽布局（不变） | 【实测】 |
| 1363×860 横屏平板（屏幕 1364×909） | 宽布局 | 宽布局（不变） | 【实测】 |
| **1363×441 横屏平板 + 软键盘**（屏幕 1364×909） | 宽布局 | **宽布局（不翻转）** | 【实测】 |
| 1400×500 矮宽桌面窗口（屏幕 1920×1080） | 宽布局 | 宽布局（不变） | 【实测】 |
| 390×844 手机竖屏 | 抽屉 | 抽屉（不变） | 【实测】 |

判定：`视口宽 ≥ 900` **且** `设备短边 ≥ 600`，其中设备短边 = `min(screen.width, screen.height)`。

**为什么不用视口高度**：11-02 在 Pad 9 Pro Max 上实测，平板横屏 1363×860 **软键盘弹出后 `innerHeight` 变成 441**（竖屏 1314→841）。任何以视口高度为准的判据都会让已 dock 的平板在输入过程中翻回抽屉布局。`screen` 的短边既不受旋转影响（宽高互换、min 不变），也不受软键盘影响，是「这是不是平板」的稳定证据。

**为什么 CSS 不再是媒体查询**：媒体查询读不到 `screen`。改为 JS 在 shell 上写 `data-dshm-wide="1|0"`，样式表跟随该属性；属性随首次渲染一起写入，因此平板不会先画抽屉带再重排。

## 改动点

### 1. 判定 · `src/mobile-layout.ts:89-176`

- `WIDE_LAYOUT_MIN_WIDTH_PX = 900`（不变）、`WIDE_LAYOUT_MIN_SHORTER_SIDE_PX = 600`。
- `WIDE_LAYOUT_ATTRIBUTE = 'data-dshm-wide'`：样式表跟随的根标记。
- `resolveDeviceShortSide(screenWidth, screenHeight, viewportWidth, viewportHeight)`：`screen` 可用时取 `min(screen.width, screen.height)`，否则退回 `min(viewportWidth, viewportHeight)`（SSR / 最小 DOM 桩）。
- `isWideViewportLayout(viewportWidth, deviceShortSide)`：两个条件都满足才 dock。视口宽度仍然参与，因此把窗口拖窄仍会退成抽屉。
- `resolveMobileRightbarLayout(viewportWidth, wideViewport, …)`：改为接收已判定的布尔值，避免第二处重复判定。

### 2. CSS：宽带从媒体查询改为根属性

| 位置 | 改前 | 改后 |
| --- | --- | --- |
| `:603`（`@layer dsh-mobile-layout` 网格所有权） | `@media(min-width:900px)` | `.dshm-shell[data-dshm-wide="1"]` |
| `:680-694`（宽布局块：drawer 静态列、main 第 2 列） | `@media(min-width:900px){…}` | `.dshm-shell[data-dshm-wide="1"] …` |
| `:636-637`（`.dshm-details` 全宽 + 48px 触控目标） | `@media(max-width:899px)` | `.dshm-shell:not([data-dshm-wide="1"]) …` |
| `:628`（折叠图标轨 56px 偏移） | `@media(min-width:721px) and (max-width:899px)` | `@media(min-width:721px){.dshm-shell:not([data-dshm-wide="1"]):has(…)}` |

**无标记 = 窄**：静态 fixture、React 挂载前的首帧都按抽屉渲染，不会出现「半 dock」的中间态。

折叠轨那条保留 `min-width:721px` 媒体查询：那是纯宽度条件（窄屏内容靠 header 内缩），与设备短边无关；横屏手机（932 宽、抽屉布局）因此也能拿到 56px 偏移，不会被固定轨道盖住——这一条是本次改动**会引入**的回归点，必须同时修。

### 3. `panelNav` 与其余 JS 消费点

- `panelNav` 条件本身不变（`:880` 仍 `activePanelId !== null && !wideViewport`），跟着 `wideViewport` 变。
- `viewportIsWide()`（`:394-407`）改用 `readViewport()` + `isWideViewportLayout`，因此 Android 返回键、点会话行关抽屉、`selectPanel` 的关抽屉判断全部一致；横屏手机上返回键先关抽屉、再退面板——与实验前提（dsh-go 横屏手机仍用抽屉、平板才常驻）一致，该前提来自任务描述，本仓库无 dsh-go 源码可核对，属【推断】。
- React 侧视口状态改为 `{ width, height, shortSide }`，在 `resize` 的 rAF 里整体重读（旋转、窗口缩放、键盘导致的视口变化都会触发）。

### 4. 测试与浏览器检查

- `tests/mobile-layout.test.ts` 判定表：932×430（屏幕 932×430）→ narrow；909×1314、1363×860（屏幕 1364×909）、**1363×441 + 键盘**（屏幕 1364×909）、909×841 + 键盘（屏幕 909×1364）、1400×500 桌面窗口（屏幕 1920×1080）→ wide；899/900 宽度边界、600 短边边界；`screen` 缺失时退回视口。
- 新增「宽带是 shell 属性而不是媒体查询」断言：属性名、四条属性选择器、以及 `MOBILE_LAYOUT_STYLES` 中**不得**再出现 `min-height:600px` / `@media(min-width:900px)`——键盘翻转的根因就写在这条断言里。
- 右侧面板表改为传已判定布尔值，补 932×430、909×1314、1363×860 与键盘场景。
- 浏览器 fixture（静态 HTML）显式带上 `data-dshm-wide`：`smoke-mobile-layout-ownership.mjs`（按 `screen` 计算）、`smoke-rightbar-fullscreen.mjs`、`smoke-opaque-chrome.mjs`、`smoke-plugin-portal-layers.mjs`。

## 风险

1. **`screen` 的语义假设。** 判据假设 `screen.width/height` 是 CSS 像素且随旋转互换（Chrome/WebKit/Blink 与 Android WebView 均如此）。若某个 WebView 返回物理像素或固定方向，短边会被高估或低估一档。退回逻辑只在 `screen` 缺失或为 0 时生效，**不能**发现「`screen` 存在但数值不合理」。真机只验证过 Pad 9 Pro Max 的 `innerHeight`，未验证其 `screen` 值。
2. **无标记即窄。** 任何不经过 React 的宿主（自建页面、旧版缓存里的旧 JS + 新 CSS）会渲染成抽屉布局。JS 与 CSS 是同一次构建产出的，正常加载不会错位；但「旧 JS + 新样式表」这种半更新状态会退化成窄布局，而不是报错。
3. **首帧依赖 React 写入属性。** 属性随 `.dshm-shell` 元素一起创建，正常不会闪；但若第三方皮肤在 shell 之外自建同构 DOM，不会得到宽带规则。
4. **旋转与键盘仍会触发一次 resize 重算。** 判定结果不变（`screen` 短边不变），但 `viewport.width` 变化会重排右侧面板的 dock 宽度；旋转瞬间可能先按旧宽度渲染一帧。
5. **`src/mobile-sidebar-scroll.ts:41` 仍用 `(max-width:899px)`。** 横屏手机现在进抽屉布局，但侧栏滚动记忆适配器在该宽度下仍按「非专用视口」处理，即退回原生滚动行为。改前改后都不生效，不是回归，但两处窄带定义现在不一致。
6. **`scripts/smoke-dsh-composer.mjs:279,287` 仍用 `(min-width: 900px)`。** fixture 是 1000×812，新旧查询都为 true，结论不变；未改（该 smoke 需要 `@deepseek-ai/dsh` 宿主 bin，本机 worktree 没有）。
